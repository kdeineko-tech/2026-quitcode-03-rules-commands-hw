# refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного шляху — ціль вказана в повідомленні
одразу після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. Зафіксуй базову лінію до будь-яких змін: `cd app && npm test` і
   `npm run check:rules` — запиши кількість порушень саме для цього файлу.
2. Прочитай `.claude/rules/conventions.md` і `.claude/rules/architecture.md`
   (посилайся на них, не копіюй сюди) і переписуй файл під них.
3. Поведінка не змінюється: той самий URL, те саме тіло запиту, ті самі
   тексти помилок — рівно те, що перевіряють існуючі тести. Не редагуй
   асерти в тесті цього файлу.
4. Заново прогони `npm test` і `npm run check:rules`, порівняй із базовою
   лінією.

## Acceptance criteria

- [ ] `cd app && npm test` зелений і до, і після — без жодної зміни в
      асертах тесту цього файлу.
- [ ] `npm run check:rules` для файлу: після — менше порушень, ніж до
      (мета — 0).
- [ ] Змінено рівно вказаний файл (його імпорти можна читати, не
      редагувати — особливо `core/`).

## Stop

Якщо довести файл до 0 порушень неможливо без зміни іншого файлу —
зупинись і опиши, що саме заважає, замість того щоб цей інший файл
міняти. Асерти в тестах не редагувати ні за яких обставин.
