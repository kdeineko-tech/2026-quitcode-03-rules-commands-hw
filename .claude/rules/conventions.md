# conventions

## Контекст

Частину коду перенесли з n8n до появи архітектурної записки, і конвенціям
він не відповідає — `npm run check:rules` показує, де саме
(`materials/architecture-brief.md`, розділи «Конвенції коду» та «Спадщина»).
Нова й перероблена спадщина мають однаково дотримуватись цих конвенцій.

## Правило

- Помилки — значення: функції, що можуть не вдатися, повертають `Result<T>`;
  `send()` інтеграції завжди повертає `Result<void>`, ніколи не кидає виняток.
- Вихідний HTTP — лише через `postJson()` з `app/src/core/http.ts` — не пряме
  `fetch`, не axios/got/ky.
- Змінні середовища — лише через `readEnv()` з `app/src/core/config.ts` — не
  `process.env` деінде; секрети не логуються і не вшиваються в код.
- Будь-який зовнішній JSON (відповідь API, тіло вебхука, файл стану) — лише
  через `parseJson(text, guard)` з guard на очікувану форму; невалідний або
  неочікуваний JSON — це `Result` з `ok: false`, а не тихе значення за
  замовчуванням.
- Журнал — лише через `log` з `app/src/core/log.ts` — не `console.*`.
- Без `any` — `unknown` плюс guard замість нього.
- Без нових залежностей — застосунок лишається з нулем runtime-залежностей;
  якщо потрібна бібліотека — спершу питання в PR, а не `npm install`.
- У сповіщення (Slack, месенджери) не передавати email і телефон ліда — лише
  ім'я, джерело й бюджет; повні контактні дані — тільки в системи обліку
  (таблиця, CRM).
- Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу.

## Як перевірити

- `cd app && npm run check:rules` — `0` для `http-via-core`,
  `env-via-config`, `json-via-parse`, `log-via-logger`, `no-any`,
  `no-new-deps`.
